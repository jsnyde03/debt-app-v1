# Phase 3.5 Coverage Audit — Synthesis & Hardened Spec (2026-07-30)

**4 Fable-5 lens-auditors; synthesis on the session model.** Goal (Jason): no gaps / no misses across the interactive tutorial + bounded demo.

## ⭐ VERDICT: the current 3.5 spec is **NOT build-ready — real gaps, incl. ~3 blockers.**
The design *skeleton* is sound (and the codebase architecture makes an isolated sandbox cheap), but the spec has load-bearing holes that would each surface mid-build or ship a defect. High cross-auditor convergence on the big ones. Fold the gaps below into the spec first, then build.

## 🔴 BLOCKERS (fix in the spec before any 3.5 code)
1. **Sandbox isolation is unspecified AND the assumed mechanism is wrong (03 + 04).** `isDemoMode` / the legacy `demoSeed.ts` **replace the real store** — persisted, widget/Siri/notification-synced, Live-Activity-armed — and fabricate `genuineCycleCount: 6` (the *matured Guardian* the demo explicitly forbids). The 3.5 sandbox MUST be an **ephemeral second store instance** (the codebase supports it — persistence/widget/notifications bind only to `appStore`), never `isDemoMode`. → **Build item #1 = `createSandboxStore(scenario)`.**
2. **The legacy "Try with Sample Data" demo contradicts (B)'s honesty bound (04, MAJOR).** It's a one-tap matured-premium user from `WelcomeStep`. Two demo systems that disagree on the core honesty constraint → must be **reconciled or replaced** by the new bounded demo, or the honesty breach ships through the back door. [DECISION]
3. **The demo has NO pre-purchase entry point (04, MAJOR) + the intro/trigger matrix is unspecced (02 + 03).** The only trigger in §3.5 is the *tutorial's* "first premium Guardian view" = post-purchase, so **only paying users would ever see the acquisition showcase.** And "absorbs the 2.4.11.3 intro" has no flag semantics → reuse `guardianIntroSeen` (intro-seen users never get the tutorial) vs a new flag (double-teach); the new-free / new-premium / upgrader / intro-seen matrix is undefined; free users get no Guardian teaching; the auto-fire isn't registered in the shipped **VIS-4 single-ack-slot** order.

## 🟠 MAJOR coverage gaps
4. **Recovery Plan — the declared TOP differentiator + the churn-moment answer — is taught/shown NOWHERE (01 + 02).** The tutorial poses "will I make it this paycheck?" but only teaches the *yes*-path. Recovery is confidence-independent (works from day-one data), so an **at-risk → Recovery** scene fits the demo's honesty bound perfectly AND supplies the legal conversion contrast the free at-risk state currently lacks.
5. **The tutorial never changes STATE (01 + 02).** It teaches the bar's zones spatially but the sandbox stays "clear"; a user never sees tight/at-risk — the whole answer-format of the headline question. Re-spec the "surprise lands" beat as a **visible clear → tight → absorbed-back-to-clear** transition. (The RS.6 e2e harness already scripts every state — the ready-made checklist.)
6. **Interactive accessibility is one un-specced word ("a11y verify") on the exact interaction class VoiceOver can't operate (02).** A drag-the-floor slider needs `accessibilityRole:'adjustable'` + increment/decrement; "watch it re-plan / absorb" conveys meaning by MOTION ALONE (needs `announce()` pairing); no reduce-motion variants; no Dynamic-Type for overlay bubbles; no VO for coach-mark spotlights. **Key insight: programmatic operability = the same work that makes the tutorial e2e-drivable** → one spec item, one exit-gate ("a VoiceOver user completes every step end-to-end").
7. **"Watch it absorb / release" are signals with no in-cycle producer (03).** `pendingReserveRelease` + the holdback release only materialize at a **rollover** (`DISCOVERY_CYCLES=3` crossing) — the step implies immediate visuals that don't exist. Need scripted pure `applyRollover` "next payday arrives" beats. Plus a hard-wire: `CushionFloorSheet.tsx:26` writes the REAL `setCushionFloor` and is mounted in the card → "drag the floor" on card-reuse mutates real data.

## 🟡 Significant gaps
8. **Instrumentation = zero, silently (04).** No analytics in the RN app ("analytics OUT" was decided *before* the demo got a launch-critical GTM role); RevenueCat shows purchases, not attribution → tutorial start/complete/skip + demo→upgrade are unmeasurable → the post-launch market audit is blind (Freedom V1.1's exact lesson). **[DECISION].**
9. **Path layer almost unwritten (02):** skip · interrupt/resume · first-fire hijacking the just-paid user · seen-flag persistence · demo **exit path** + persistent "Demo" indicator + edit-in-demo semantics · sequencing vs the VIS-4 ack coordinator.
10. **Coach-marks (C) target list is 2 items but the shipped surface has ~9 hidden/unfindable entries (01 + 02):** long-press context menu · Cash-Runway drag-scrub · Can-I-Afford · the income-varies toggle · swipe-to-delete · chart scrub · the double-hidden "Log payment" · Siri/widget/Lock-Screen. Enumerate them. Coach-marks must render OUTSIDE `GestureDetector` (the shipped tap-swallow lesson) + platform-gate iOS-only targets (the long-press menu base is a web/Android passthrough) + zero coach-mark infra exists today.
11. **The honesty/on-device moat is never STATED (01)** in (A)/(B) — one wrap-line/caption ("engine-grounded · can't fabricate your numbers · private by default").
12. **No scorecard / earn-trust beat (01)** — the tutorial's audience is exactly the just-converted, guarantee-window buyer; extend the wrap beat with a "here's what I'll show once I learn you" scorecard + the notification contract.
13. **Free-tier "?" entry undefined (02)** — recommend free users can run the tutorial as the value-led taste (pairs with the demo's pre-purchase reachability).
14. **GTM double-duty (04):** the sandbox should be required to serve as the deterministic **App-Preview-video / screenshot capture path** (cheap now, double-work at Phase 6). **Localization (04):** all new 3.5 copy + sandbox currency/date locale-neutral (no new inline `'en-US'`) since v1.7 ships AU/NZ. **Both-theme (02):** the verify gate is on (A) only — extend to (B)/(C).

## ✅ Scope guardrail (auditors agree — do NOT over-build)
Hold the line against turning the tutorial into a feature tour: **no** Can-I-Afford / BNPL / Windfall / graduation *beats* in the tutorial — those belong to coach-marks (C) + in-app discovery. The tutorial stays the ONE core arc (Guardian read → your line → reserve → safe move → your call), now with a real state transition + a Recovery glimpse + the trust/scorecard wrap.

## ▶ HARDENED, DECOMPOSED 3.5 BUILD ORDER (gaps folded)
_Build in this order; the substrate contract is first so no step hits a missing producer._
- **3.5.0 — `createSandboxStore(scenario)` substrate [BLOCKER-fix].** Ephemeral second store instance · frozen base date · `inputsAsOf` pinned · `genuineCycleCount ≤ 1` (the cold-start bound then enforces itself) · scripted pure `applyRollover` "next payday arrives" beats (for absorb/release) · NEVER persisted / widget- / notification- / Live-Activity-synced · sandbox floor slider mirrors the real snap-$25 / cap-$1000 clamp · `isDemoMode` explicitly declared NOT this mechanism.
- **3.5.1 — Trigger/intro matrix + reachability [BLOCKER-fix].** Define exactly what fires for new-free / new-premium / upgrader / intro-seen; a new `tutorialSeen` flag (not `guardianIntroSeen`); register the auto-fire in the VIS-4 single-ack-slot; wire replay entries (the "?" on the card + a "How the Guardian works" More row — neither exists yet) + a **free-tier** run as the value-led taste.
- **3.5.2 — Interactive-a11y + path scaffold [MAJOR-fix].** Stepped-flow scaffold with skip / interrupt-resume / seen-persistence; every interactive step VoiceOver-**operable** (adjustable slider + `announce()` on motion-only changes) + reduce-motion variants + Dynamic-Type; **exit-gate: a VoiceOver user (and the web e2e) can complete every step end-to-end.**
- **3.5.3 — The tutorial arc on the sandbox:** meet it → read the bar (tap zones) → **your line** (drag the floor → live re-plan, crossing **clear→tight**) → **the reserve** (surprise lands → **tight→absorbed→clear** via a scripted rollover) → **a Recovery glimpse** (one scripted at-risk→"safe to defer" card, not a walkthrough) → the safe move + "your call" → **wrap** (scorecard "once I learn you" + on-device/honest moat line + notification contract). Both-theme + a11y verified.
- **3.5.4 — Bounded demo (B) + GTM funnel [BLOCKER/MAJOR-fix].** A scripted run of the tutorial on the sandbox, day-one-bounded (floor auto-protect · tight one-tap · water-fill smoothing · scorecard-as-future · reserves HELD) + the **free at-risk → Recovery** contrast. **Pre-purchase entry:** a Welcome-step slot + a paywall "See it in action" + a free-Guardian teaser; first frame answers the paycheck question in ~5s; exit CTAs "Start my real plan" / "Unlock Premium". **Reconcile/replace the legacy `demoSeed.ts`** so no matured-Guardian demo remains. Doubles as the deterministic App-Preview/screenshot capture path. Locale-neutral copy.
- **3.5.5 — Feature-discovery coach-marks (C):** on-brand RN coach-marks (calm · one-at-a-time · dismissible · replayable · iOS-16-safe · rendered OUTSIDE gesture handlers · platform-gated) over the **enumerated** hidden-gesture inventory (long-press menu · Cash-Runway scrub · Can-I-Afford · varies-toggle · swipe-to-delete · chart scrub · Log-payment · widget/Lock-Screen/Siri nudges).
- **3.5.6 — verify + close:** both-theme + a11y (VO end-to-end) + e2e; whole-3.5 after-scan → the whole-app cohesion + wording/voice audit (already the next gate).

## 🔷 [DECISION]s for Jason (each with a recommendation)
- **D-A · Instrumentation:** wire a privacy-first, opt-out event seam (Freedom's pattern; ~8 funnel events: tutorial start/complete/skip · demo view/engage/replay · demo→paywall · demo→upgrade; **no financial data**) — **OR** ship deliberately blind. **Rec: wire it** — the demo is launch-critical GTM and we can't tell if 3.5 works without it; it stays within the on-device/privacy moat (no financial values, opt-out).
- **D-B · The legacy `demoSeed.ts`:** **Rec: replace it** with the new bounded demo (retire the one-tap matured-Guardian sample) so there's ONE honest demo system.
- **D-C · Free-tier tutorial/demo access:** **Rec: yes** — free users can run the tutorial + hit the bounded demo (the value-led taste + the pre-purchase acquisition showcase); premium is still where the real Guardian acts.
