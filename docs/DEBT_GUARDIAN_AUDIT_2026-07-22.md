# Payday Cushion Guardian — Lock-Down Audit (2026-07-22)

Four independent adversarial lenses (correctness · trust/premium-defensibility · UX/IA/a11y · product-completeness) on the Guardian design + built code (2.4.1–2.4.6 shipped; 2.4.7 designed, unbuilt). Deduped + ranked by **action**, not by lens. The feature is strong; this is what stands between "works in the demo" and "locked down."

> **Two structural root causes** account for a third of the findings. Fixing them dissolves the rest:
> 1. **One metric, everywhere.** The band uses floor-relative *headroom* (`discretionary`), but the lookahead + the Progress cash-flow bars still use `endingBalance` (deployable-after-buffer vs fixed 200/100 thresholds). Same cycle → contradictory reads.
> 2. **An exhaustive partition of discretionary.** The Guardian models only two buckets (cushion, debt) but the engine deploys into four (buffer/leftover, **emergency fund**, snowball, **optional goals**). During the common EF-funding phase the accounting silently doesn't balance.

---

## TIER 1 — Confirmed live bugs in shipped 2.4.6 (fix before 2.4.7 builds on them)

1. **Lookahead fires false "next cycle looks tight" for ~every premium user.** The `endingBalance`-trap was fixed for the current band but NOT the lookahead: `guardianSelectors` reads `upcoming.endingBalance`/`cushionStatus` (deployable-after-floor, scored vs fixed 200/100). A healthy future cycle with $350 headroom and a $200 floor → `endingBalance ≈ $150` → "tight." **Worsens as the user raises their line** (higher floor → more subtracted → more "tight" alarms) while the card invites "raise your line." Violates the HARD no-false-alarm rule and makes the card contradict itself. *(correctness #1, #8 · trust #6 · = 2.4.6 follow-up (ii))*
2. **EF/goals-phase copy lies: "all held as your cushion" when it isn't.** `kept`+`deployed` ≠ `discretionary` whenever the engine funds an emergency goal or optional goal (both are non-obligation outflows the two-bucket model drops). Baby-Step-1 user, $600 headroom, EF eats $400 → card says "$600 … all held as your cushion — right at your $200 line." Contradictory and overstates the cushion. *(correctness #2, root-cause 2)*
3. **A one-time windfall is applied to every projected future cycle.** `buildMultiCycleTimeline` reuses `result.paycheckAmount` (which includes `windfall`) for all cycles → a $2,000 refund fabricates +$2,000 in every future cycle → phantom surplus (also poisons 2.4.7 smoothing). *(correctness #3)*
4. **`at-risk` cutoff is hardcoded `discretionary < 100`, floor-independent.** User with a $50 line and $80 headroom → "Very tight … under your $50 line" — but $80 is *above* $50. Copy asserts the opposite of the truth. *(correctness #5)*
5. **`focusDebtName` can name the wrong debt.** It re-ranks debts independently (`rankDebts[0]`) instead of reading the actual first `snowball` allocation, so a fully-covered smallest debt (or one not due this cycle) is named as the destination while the extra actually rolls elsewhere — a false-precise action. *(correctness #6)*
6. **Hedging rounds small amounts to "$0."** `about(2)` → "$0"; a $2 shortfall renders "about $0 short" / "$0 left" — an at-risk state that reads broken. Floor the hedged nonzero at one step. *(correctness #7)*
7. **[a11y BLOCKER] VoiceOver can't reach "Adjust your line →".** The whole card body (incl. the `Pressable`) is wrapped in one `groupLabel` (`accessible:true`) container, which collapses descendants → the flagship control is unreachable by screen reader. Render the control as a sibling *outside* the narrated container. *(UX #1)*
8. **"Adjust your line →" shows during shortfall/at-risk** — its only function is sending *more* to debt (lower floor), contradictory when money is tight. Hide when `at-risk`/`shortfall>0`. *(UX #3 · = 2.4.6 follow-up (iii))*
9. **The "calm" bar replays its 700ms grow on every incidental re-render** (effect deps include `cushionFrac`/`payoffFrac`), so it re-animates when marking an action, editing the floor, or rollover — the opposite of the calm register. Run intro once on mount; tween value changes quietly. *(UX #6)*

## TIER 2 — Honesty & framing reshapes (root-cause fixes + copy; some decide-with-Jason)

10. **Reframe the promise off omniscience.** The Guardian answers "will I make it this paycheck?" from *entered* data only — the no-Plaid moat means it can't see your bank. A user with $5k in checking gets told "at-risk." Reframe to **"will your *plan* hold this cycle,"** and state the boundary once ("based on what you've entered — not your bank") — as the honest *reason* the on-device story is a feature, not a limitation. *(trust #1)*
11. **Guard false-*reassurance*, not just false-alarm.** Every doc guardrail points at the scary alarm; the more harmful error for a debt app is "you're covered" → user deploys cash to debt → a surprise the app never saw → overdraft. Hedge the *clear* state too; never let "covered" read as a guarantee. *(trust #3)*
12. **Present-tense *plan* voice, not past-tense *action* voice.** "I'm holding / I paused / I sent" implies custody/execution; nothing is literally moved (mark-paid is manual). Use "Your plan keeps $X as cushion and sends the spare to debt — mark it when you're ready." Reserve completed-action language for things actually executed. *(trust #5)*
13. **Add hysteresis + floor-relative thresholds to the state machine.** A sub-$25 projection swing flips tight↔clear *and the card color* — a false-precise verdict relocated from the dollar figure into the band. Add a dead-band around boundaries; one definition of "tight," used by band + lookahead + bars. *(correctness #5 · trust #6)*
14. **Reconcile the divergent "cushion" numbers on Today.** Hero "Free $210" vs Guardian "$160 cushion" vs the cash-flow bar's `endingBalance` — three adjacent figures that disagree read as "which is real?" on a trust-moat product. Distinct non-overlapping labels or one anchor. (Largely dissolved by root-cause 1.) *(trust #7 · UX #4 · correctness #8)*
15. **Soften the FREE at-risk state.** A stressed free user currently gets a red shield + "Tight this paycheck" with *no* safe move, *no* lookahead, only an upgrade line — anxiety-to-upsell. The value-led rule must hold in the scary state: the taste still *helps*. *(UX #3)*
16. **Exhaustive discretionary partition + reconciliation test.** Model the real four buckets (cushion + EF + debt + goals + true-leftover) that provably sum to `discretionary`; drive the bar + copy + a11y label off it. This is the structural fix under #2/#14 and the foundation 2.4.7 needs. *(correctness "what's missing")*

## TIER 3 — [DECISION] gates for Jason (before / within 2.4.7)

17. **The debt-free / graduation capstone has no render home.** `selectPaydayGuardian` returns `null` the moment `liveDebts=0`, but the waterfall *ends* at "debt-free & funded → Freedom." The arc's finale fires exactly when the Guardian nulls itself out. **Decide:** does the Guardian (or a successor surface) persist past debt-free to deliver the capstone? *(completeness #1)*
18. **Variable / irregular income is entirely unmodeled** — and it's the sibling app's whole audience (gig/hourly/tips). The Guardian reads `paycheck.amount` as a fixed scalar; "will I make it this paycheck?" is *most* acute for people whose income swings, and there's no ranged/uncertain-income notion anywhere. **Decide:** explicit "v1.7 assumes stable income; ranged income = named v1.8 item" + a conservative interim, rather than silent omission. *(completeness — biggest undiscussed)*
19. **Does the Guardian, standalone, pass "removes WORK not info"?** Free already shows the real read; premium adds a config number + two sentences (the exact smart-text the reshape demoted). The genuine work-remover is 2.3 + the 2.4.7 auto-pre-funding. **Decide:** the Guardian's premium value must visibly *do* something free can't (2.4.7), or be marketed as one face of the automation *bundle* (2.3+2.4.7), not a standalone $4.99 justification. *(trust #2)*
20. **"Watches every paycheck" is unbacked.** The Guardian only recomputes when the app is open; notifications exist but are schedule-generic, not Guardian-state-aware. **Decide:** soften the copy until a shortfall/at-risk local notification ships, and make that notification an explicit *required backer* of the proactive claim at 2.6/2.9 (not optional). *(completeness #2)*
21. **A calibration loop — the Guardian has no memory of being wrong.** It makes a projected claim every cycle and never reconciles it against what happened → repeated near-misses compound into "cries wolf" with nothing to arrest it. The verify loop reconciles *balances*; there's no "was the Guardian right?" loop for *forecasts*. **Decide:** a lightweight self-scorecard, or soften claims until the projection has survived a real cycle. Nearest home: 2.6. *(trust "novel" · completeness secondary)*
22. **EF/waterfall can be wrong or preachy on incomplete data.** It can't see an EF held elsewhere (bank / a partner / the Freedom app) → tells a $20k-in-savings, 29%-APR user to divert from the card to build an EF they already have. And it can't truly know which costs are "flexible." **Decide:** gate the EF rung behind "already have savings elsewhere?" (absence never assumed = need); offer EF-first-vs-APR-first as a *choice with a why*; for structural deficits, state the *gap* without naming/blaming a guessed category. *(trust #4 · completeness #7)*
23. **2.4.7 timing-vs-structural test is mathematically wrong.** `sum(surplus) ≥ sum(deficit)` ignores ordering (money can't flow backward): a cycle-1 deficit rescued by cycle-5 surplus is *not* smoothable. Use a **running prefix-sum** (`cumulative_surplus(1..k−1) ≥ cumulative_deficit(1..k)`); the timing/structural boundary is the first cycle the prefix test fails. Also expose a clean per-cycle **net** (income − required − living) + per-cycle discretionary from `buildMultiCycleTimeline` — do NOT reuse `endingBalance`. Note the ~6-cycle horizon hides quarterly/annual bills — the ones that most need pre-funding. *(correctness #4)*
24. **Where the drill-down lives + Today overload.** Today already stacks hero → Guardian → Required → Recommended → provisional-payoff → payday nudge → stale-balance; 2.4.7 adds a multi-step plan + a "Cash-Flow Plan" view, and Progress *already* owns a cash-flow section answering the same question. **Rec:** drill-down = a **route** = the elevated Progress cushion view reached *from* the Guardian (one destination, two entry points); card summary strictly ≤3 lines. *(UX #2)*

## TIER 4 — Deferred / polish / capture

- **Floor-line motif doesn't cohere with the Progress cushion bars** — Guardian is Skia + tokens, Progress is RN gradient + hardcoded hex + no floor line. Unify the state palette into shared tokens and carry the floor line into the Progress bars (the 2.4.7 forecast is speced to draw it "across" — same renderer/treatment). *(UX #4)*
- **The cushion floor has no first-run introduction** — defaults silently to $200; onboarding never mentions it; the only setter is inside the premium card. A one-line intro / "we set your line at $200 — sound right?" at first premium use. *(UX #7 · completeness #6)*
- **The flagship is invisible in the demo** — `demoStore()` ships `subscriptionPlan:'free'` and demo disables Autopilot, so try-before-buy + store screenshots can't show the acting Guardian. Needs a scripted Guardian showcase (a tight cycle + a flush cycle) for Phase-6 store presence. *(completeness #3)*
- **Guardian ships (2.4) before the accuracy layer (2.5)** — a miscounted lapsed-trial/BNPL inflates `totalRequired` → false shortfall. Interim mitigation = the min-only conservative bias + hedged copy; document the interim risk. *(completeness #4)*
- **Drift → Guardian contract is undefined** — "absorbs Drift as a trigger" but `GuardianInput`/`Brief` have no drift field; define the input + resulting brief change at 2.6 switch-in (+ the anchor unification, 2.4.2). *(completeness #5)*
- **iPad / dynamic-type / high-contrast** — the fixed-14px full-width bar becomes a thin sliver on iPad; long hedged sentences at AX sizes; bar state is color-only (redundant with the shield, but untested in high-contrast / reduce-transparency). Phase-6 device + AX-size + contrast pass. *(UX #5, #7)*
- **min-only projection bias** — the Guardian's dollar moves ride a deliberately conservative (min-only) projected balance while presented as the live plan; reconciliation note. *(correctness secondary)*

---

## Verdict

The Guardian is the strongest premium spine the app has, and the concept survived every lens. But the **built 2.4.6 has correctness + honesty gaps that 2.4.7 would amplify**, so the right order is: **harden first (Tier 1 + the two root-cause fixes in Tier 2), decide the Tier-3 gates, then build 2.4.7 on the hardened base.** Nothing here kills the design; it sharpens it.
